# 비교 계산 비용

2026-10-02, macOS 27 arm64 / CPython 3.14.6에서 합성 문자열로 측정했습니다.
이 수치는 STT 모델의 품질이나 처리 속도가 아닙니다. warm-up 후 3회 중앙값이며,
메모리는 별도 tracemalloc 실행의 peak입니다. 측정 중 다른 프로세스의 영향은
통제하지 않았으므로 다른 환경의 성능을 보장하지 않습니다.

| 입력 | 이전 시간(s) | 재사용 후(s) | 이전/이후 peak(bytes) | 편집거리 호출 이전→이후 |
| --- | ---: | ---: | ---: | ---: |
| 12자 × 2문장 × 2시스템 | 0.003542 | 0.001019 | 194442 / 194218 | 20 → 8 |
| 300자 × 2문장 × 2시스템 | 0.263265 | 0.081984 | 197698 / 197314 | 20 → 8 |
| 24자 × 20문장 × 4시스템 | 0.065268 | 0.021741 | 212066 / 211618 | 400 → 160 |
| 24자 × 20문장 × 2시스템, bootstrap 200회 | 0.039282 | 0.014214 | 202448 / 202224 | 200 → 80 |

이전 기준은 `eb57d46`입니다. 재사용 후에는 각 문장 쌍의 CER/WER 편집 통계를
한 번 구하고 CRR·집계·bootstrap이 이를 사용합니다. 단독 지표 함수, 정렬 동률
선택, CRR 반올림과 빈 참조 정책은 그대로입니다.

```bash
python -m benchmarks.comparison_baseline --label current --output comparison-benchmark.json
```

CI는 시간 배수 대신 **문장 수 × 시스템 수 × 2회**라는 기본 편집거리 호출 예산을
검사합니다. 환경 편차가 큰 wall-clock 기준으로 릴리스를 막지는 않습니다.
선택적 키워드·개체명·진단은 별도 작업이므로 이 호출 예산에 포함하지 않습니다.

기본 정렬 시간은 여전히 입력 길이의 곱에 비례하고, 비교용 문장별 통계 메모리는
문장 수 × 시스템 수에 비례합니다. bootstrap·문장 상세·조건별 집계를 모두 끄면
이미 요약한 시스템의 문장 통계를 따로 보관하지 않습니다.
설명/진단의 전체 정렬 행렬은 O(n*m)입니다.
긴 녹음 전체를 한 문장으로 넣기보다 의미 있는 문장 단위로 나누세요. 이번 측정만으로
입력 상한이나 새 고속 backend를 도입하지 않았습니다. 실제 긴 입력이 필요하면
정렬 동률과 normalized 분모 일치를 먼저 검증해야 합니다.
